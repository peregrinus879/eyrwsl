# AGENTS.md - EyrWSL

Self-contained Arch WSL dotfiles adapted from [Omarchy](https://github.com/omacom/omarchy) and managed with [GNU Stow](https://www.gnu.org/software/stow/). EyrWSL owns the terminal baseline plus WSL and Windows behavior. Omarchy's pinned baseline, official documentation, and `DEVIATIONS.md` define defaults, intentional differences, and ownership boundaries.

## Load Map

- Claude Code loads this file through the root `CLAUDE.md` `@AGENTS.md` import; skills load on invocation only.
- The `Makefile` is the single source of the package list (`scripts/verify.sh` and `scripts/prepare-stow.sh` consume it); `references.txt` lists the reference clones `/omasync` needs, and the family union of those files owns `~/Projects/quarry`; `README.md` carries the human-facing setup, verification, and maintenance detail; script headers own local constraints.
- `docs/maintenance.md` owns unresolved decisions, deferred work, active limitations, and dated revalidation evidence; read it before package, WSL, or Windows Terminal changes, `/omasync`, or deferred work. Prose describes current behavior; Git history owns provenance.
- EyrAgents' canonical [Workstream Checkpoints](https://github.com/peregrinus879/eyragents/blob/main/agents/.agents/shared-guidance.md#workstream-checkpoints) rule owns local continuity for substantial work. The primary owns the gitignored `.eyr-plans/<workstream>.md` milestone summary and reads it on resume, compaction, and handoff; no extra skill is needed. It is not authorization or cross-machine transport. Retain completed local checkpoints; remove session scratch.

## Invariants

- Target machine: WSL2 with active Windows interop. The host guard requires enabled `binfmt_misc` and an enabled `WSLInterop` or `WSLInterop-late` handler, resolving `clip.exe`/`powershell.exe`, and a successful five-second, no-profile PowerShell probe; configured intent alone is insufficient. `stow`, `unstow`, `restow`, `clean`, `verify`, and `wt-push` refuse elsewhere. Every host-writing Make target requires the deployed-clone guard before mutation, checking managed endpoints and parents; `.NOTPARALLEL` serializes one Make invocation, not independent deployments. Direct `scripts/wt-diff.sh --push` also invokes the guard before destination discovery. `lint`, `check`, `test`, `twins`, `twins-pair`, and `refs` run anywhere.
- Because the packages are live configuration on the stowed host, an edit to a stowed file here is active for the next shell, Git command, Neovim session, or tmux server before any commit; work on this repository only in a session H is watching. `git/.config/git/config` is live for every Git command through its stow link and carries `[alias]` and `[include]`, so an alias or include edit is a code-execution change; it is diff-visible, which is why it stays inside the edit boundary rather than behind a deny.
- Stow runs with `--no-folding`, so every managed parent under `$HOME` is a real directory and only leaf files are links; generated host state therefore never reaches a package source. `make clean` preflights the complete owned layout and removes only owned folded links and recognized dangling clone links. Regular files, foreign links, and special files refuse unchanged; an owned pathname is not proof of disposable content. `make verify` fails on a folded managed directory. Preflight is preservation-safe refusal, not rollback against I/O failure or concurrent host edits.
- When editing sibling dotfiles repos, use identical wording for shared concepts; only repo-specific values (scope, package lists, invariants) differ.
- `git-review.lua` keeps Git diff/origin-diff/status tied to the current file or Neo-tree selection, not an unrelated launch directory. Resolve the context on each key invocation without changing editor cwd; known non-Git targets warn rather than choosing another repo. The spec and regression suite are twins; keep upstream base config and plugin caches untouched.
- The Makefile `TWIN_SPECS` files (Neovim plugin specs, `tdw`/`hdw`, Yazi config, reference updater, and their declared tests/fixtures) are byte-identical across EyrArcHy and EyrWSL. Local `make twins` checks worktrees and can skip a missing sibling. `twins-pair` carries `SELF_COMMIT`, `PEER_COMMIT`, and `SIBLING` as literal data, not Make expressions or shell source; it requires two full commit IDs and compares committed blobs, failing on missing objects/files without executing peer code. CI checks the peer default branch normally; an explicit manual-dispatch peer requires `peer_reviewed=true` and records both actual commits. Final publication evidence must name the final published pair, not an arbitrary earlier green peer.
- `make refs` reports and keeps stale clones, never inferring deletion safety from HEAD or cleanliness. Listed default branches must reach exact fetched upstream parity by fast-forward; ahead-only/divergent branches refuse. Atomic, non-forced fetches preserve existing local tags and annotations while importing new tags and pruning only origin tracking branches. Checkout and merge use `--no-overwrite-ignore` to preserve ignored files in listed clones. Tag/file conflicts refuse that update and require separate review, not forcing or deletion. Manual disposal needs separate review of all refs, stashes, and ignored/untracked content.
- `tdw`/`hdw` keep project session/workspace names and name only new windows/tabs `claude`, `codex`, or `opencode`; existing names/layouts stay untouched. Creation is serialized, validates ownership and the complete layout before input, and rolls back only its own creation. Herdr startup failure returns failure; unverified rollback retains reported recovery evidence for manual review. New tmux titles retain `#h:#S:#W`. These multi-call workflows are not server-side atomic transactions.
- `make verify` must fail closed across WSL2/interoperability, commands, the AI tools installed by and resolving through a paranoid-mode mise, deployment ownership with real managed parents, Git identity (a GitHub no-reply address, never printed), and config parsing; fixture overrides must not weaken normal mode and never target the live home.
- Gruvbox is the only configured theme. Windows Terminal and btop use Omarchy's palette, Neovim uses Omarchy's `ellisonleao/gruvbox.nvim` selection, and ANSI-aware applications inherit the terminal palette.
- `nvim/` owns the complete LazyVim bootstrap, static configuration, and generated plugin lockfile; setup requires no separate config clone.
- Git identity lives in the untracked per-host `~/.config/git/config.local`; `make verify` asserts that it resolves to a GitHub no-reply address without printing it.
- Shared AI agent harness and OpenCode TUI configuration stay in EyrAgents, which deploys its own packages with `make stow` in its clone; nothing here touches `~/.config/opencode`, and EyrWSL carries no custom OpenCode theme.
- Node.js is an EyrAgents verification prerequisite, not part of EyrWSL's package baseline or a runtime dependency of the prebuilt AI binaries. Native global OpenCode guidance, auditor/scratch policies, and commit/publication/reviewer procedures remain EyrAgents-owned.
- `ga` resolves the actual checkout root; `gd` accepts no arguments, confirms the real linked-worktree path and branch, and refuses dirty work or a HEAD not contained in the primary worktree's current HEAD before non-forced removal. Navigation uses literal builtin directory changes, not interactive aliases. Branch-deletion failure retains the branch and reports the partial outcome; there is no helper force option.
- `rsw` keeps monitoring/event consumption active during transfers, retries failed transfers after five seconds, and checks a 60-second reconciliation threshold between transfers without `--delete`. Source resolution preserves literal paths despite navigation aliases, `CDPATH`, or trailing newlines. Readiness is published as a complete record, not transfer success; logs carry failures. `lsw`/`dsw` manage only watchers created by this implementation, using checked readiness records and process arguments, not broad process-name matching.
- Neovim's WSL clipboard provider requires `powershell.exe`, not `clip.exe`, and uses argv arrays with explicit UTF-8 input/output, `-NoProfile`, and terminating-error behavior. Copy/paste cover both `+` and `*`; empty/null and CR handling must be verified on the actual Windows boundary, not inferred from mocks.
- Packages come from official Arch repos, `mise` included. Claude Code, Codex, and OpenCode are installed and updated through mise by the wrappers the `mise` package stows into `~/.local/bin`, the files `omarchy-mise-install` writes on Omarchy; `~/.config/mise/config.toml` and `~/.local/share/mise` are host state those wrappers create, never package sources. The same package stows `~/.config/mise/conf.d/eyrwsl.toml`, which turns on mise's paranoid mode, and the wrappers and `mup` keep mise's default release cooldown, unlike Omarchy's. Herdr uses its canonical installer while no official package exists. No AUR packages or helper.
- `windows-terminal/settings.json` is a full paste-ready config, never stowed; deploy it explicitly with `make wt-push`.
- Keep every intentional difference documented in `DEVIATIONS.md`; update `README.md`, `AGENTS.md`, and `DEVIATIONS.md` together when ownership, setup, or sync assumptions change.
